# Verification

- API: run `npx tsc --noEmit` and `npx jest --coverage --runInBand` from `apps/api`.
- AutoPilot PostgreSQL outbox tests use `AUTOPILOT_TEST_DATABASE_URL` pointing to a dedicated disposable database with the Prisma schema applied. In CI they use the CI `DATABASE_URL`. They create isolated fixtures and a migration probe schema; never point them at production. When provisioning a disposable PostgreSQL server, also create an empty `app` database before applying migrations to the test database: the legacy RLS migration grants CONNECT on `app`.
- API auth integration tests use Redis through FeatureFlagsService. Supply a dedicated disposable test Redis with `REDIS_URL`; do not point tests at production Redis. Disable SMTP for tests with `SMTP_HOST=`.
- Web: run `npx tsc --noEmit` from `apps/web`. Target Jest files with `npx jest --runInBand --runTestsByPath '<path>'` (quote paths containing parentheses).
- Cron-owned AutoPilot operations require `PrismaSystemService`; request-scoped `PrismaService` uses the `app_runtime` role and portfolio/position RLS fails closed without a user context.
- AutoPilot paper positions are managed only by the durable event worker. Generic position/trailing watchers must exclude `AUTOPILOT_EMAIL`. Outbox migration marks existing events `HISTORICAL`; do not reset old entries for automatic replay.
- Signal execution events describe theoretical price tracking, not proof of a paper portfolio position or a broker fill. Verify linked positions separately.
- Admin AutoPilot supervision uses `GET /admin/ops/autopilot`, restricted to ADMIN/SUPER_ADMIN. Its system-client portfolio reads must remain scoped to `AUTOPILOT_EMAIL`, name `AutoPilot`, type PAPER; never accept a client-supplied system portfolio/user ID or create a portfolio from this read endpoint.
- Portfolio Manager defaults to the personal portfolio tab. System AutoPilot Paper is an admin-only, separate tab, not a section above personal positions. Its selection must not change the personal Demo/Real selection, worker state, or execution configuration; its polling component is unmounted when inactive.
- AutoPilot `Position.pnl` already includes realized partial exits. Do not add `partialPnl`/`secondPartialPnl` again. The supervision view marks remaining quantities with closed 1m candles only (open time 1–5 minutes old); missing/stale marks mean unavailable latent P&L/equity, not zero.
- `AutopilotMarksScheduler` (`apps/api/src/admin/autopilot-marks.scheduler.ts`, cron `AUTOPILOT_MARKS_ENABLED`, every minute) fetches and stores 1m candles via `HybridCandleRepository` for symbols with open positions in the AutoPilot system portfolio only — it never reads user portfolios or touches positions. This is the only supported source of fresh marks; the snapshot reader deliberately has no provider/broker fallback.
- Keep production deployment CI-driven. Do not change execution mode, enable live venues, or send broker orders during paper-pipeline verification.
- Jupiter: `apps/engine/utils/jupiter_quote.py` is a separate Swap V2 quote-only reader; the execution adapter remains on legacy V6 and is not redirected. It never loads wallet keys or submits transactions. Reuse one reader instance for keyless pacing (at least 2.1s between requests). Amounts are raw u64 integers, not dollars or floating-point quantities. Quotes have a maximum local lifetime of 15s (network latency included); consumers must call `require_fresh()` before use. Tests from `apps/engine`: `python3 -m pytest tests/test_jupiter_quote.py -q`. A quote is not a fill or a guarantee of execution. Verify both original SPL and Token-2022 programs when reading wallet token accounts, using finalized commitment and integer token amounts.
- Hidden Gems Jupiter checks use V2 quote-only round trips, not the legacy V1 URL. The public scan budget remains 8 seconds, with at most two Solana candidates checked sequentially; the remainder are explicitly DEFERRED and never implicitly verified. API/rate-limit failures and stale/rejected quotes keep sellability unknown and do not trigger a honeypot penalty. Only exact documented machine routing codes on HTTP 400 are classified as NO_ROUTE; ambiguous text is unknown. V2 `priceImpact` is already in percentage points (no magnitude-based conversion). Tests: `python3 -m pytest tests/test_jupiter_quote.py tests/test_jupiter_check.py tests/test_gem_jupiter_checks.py tests/test_phase_l.py -q` from `apps/engine`.
- Read-only venue preflight: `python3 tools/check-venue-connectivity.py --binance both --solana mainnet`. Binance hosts are pinned to Spot Demo and Futures Demo; `--authenticate` prompts for rotated keys in a masked terminal and never saves them. Solana accepts only a public address (`--solana-address`), not a private key. Tests: `python3 -m unittest discover -s tools -p test_venue_connectivity.py`. Do not use `tools/test-binance-adapter.py` for connectivity checks: it submits orders.
- Admin MT5 monitoring uses only `MT5_READ_BRIDGE_URL` and `MT5_READ_BRIDGE_TOKEN`, never the execution connector's `MT5_BRIDGE_*` settings. Its Docker URL is `http://mt5-read:5555` on the external `trading-mt5-read` network; create that network before deploying the API (the sandbox start script also creates it). Keep the token server-side; the admin endpoint returns only sanitized demo snapshots.
- MT5 activity reads (`/orders`, `/history/orders`, `/history/deals`, `/activity`) are demo-only, verify identity before/after the locked reads, and distinguish MT5 `None` failures from empty results. History requires timezone-aware dates, defaults to 7 days, caps windows at 31 days, and pages at 100 rows (maximum 200). Tickets and magic IDs are strings to preserve 64-bit precision. The admin `/admin/ops/mt5/activity` reader uses only read-bridge settings, returns sanitized first-page data, and indicates partial histories; the UI requests it only when expanded. Broker specifications do not validate sizing/margin, and multiple broker reads are not an atomic trading snapshot. Deal history includes balance/credit operations, so a deal count is not a trade count. Cold Wine startup can exceed a 120s probe window; wait for authenticated demo readiness after service startup rather than treating the container healthcheck as broker connectivity.
- MT5 bridge unit tests: install `apps/engine/requirements-test.txt`, then run `python -m pytest tests/test_mt5_bridge.py -q` from `apps/engine`; MT5 is mocked and no broker is contacted.
- MT5 order sizing (`apps/api/src/execution/mt5-sizing.ts`, used by `mt5.connector.ts`): `OrderParams.quantity` is always base units, converted to lots via the real `/contract/<symbol>` specs (floor to `volume_step`, reject below `volume_min`/above `volume_max` — never clamp up). Orders fail closed without contract specs or a live quote; SL/TP must satisfy `stops_level × point`; `takeProfit` is forwarded to the bridge. After an ambiguous order response (timeout/5xx), the connector reconciles via `/history/deals` (magic `20261118` + symbol) before reporting failure — no blind retry. Fixed margin is checked only when `margin_initial` is published.
- The separate MT5 sandbox uses `tools/mt5-bridge/compose.yaml`; build with `docker build -t trading-os-mt5-sandbox:local tools/mt5-bridge`. Its browser/API ports bind only to loopback, it has a dedicated Wine volume, and its startup forces API read-only mode. Never copy the host Wine profile or broker credentials into it automatically.
- Sandbox expected-account settings belong in the ignored `tools/mt5-bridge/.env.identity.local` (`MT5_EXPECTED_LOGIN`, `MT5_EXPECTED_SERVER`), separate from auto-login credentials. The confirmed sandbox terminal uses non-portable mode; do not add `/portable` on restart or it may select a different account profile. Container health checks test authenticated service availability, not broker connectivity; check `/health` separately for `connected`, `identity_matches`, `account_mode`, and `ready_for_read`.
- Hidden Gems paper trading (`ml/gem_paper_trader.py`, cron 10min) opens virtual positions on qualified gems; entry marks use Dexscreener spot prices, not executable sell quotes — latent P&L is optimistic by the spread/impact. Solana entries additionally require a VERIFIED Jupiter sellability check (`exec_check.checked && exec_check.sellable`); DEFERRED/UNAVAILABLE block entry via `_paper_entry_ok`. Closed trades persist to `gem_paper_trades`; open positions live in Redis only (lost on flush).
- Jupiter GEM adapter (`risk/adapters/jupiter.py`) signs real on-chain swaps. It registers ONLY when `GEM` is in `EXECUTION_LIVE_VENUES` (keypair not loaded otherwise). `place_order` refuses when `GEM_TRADING_DISABLED=1`, caps notional at `GEM_MAX_TRADE_USD` (default 25), bounds slippage at `GEM_MAX_SLIPPAGE_BPS` (≤500), and re-checks sellability via `check_exit_liquidity` immediately before signing — a refused check blocks the swap. `close_position` requires the exact on-chain token balance.
- Crypto macro phase coupling (`risk/macro_rotation.py` + `risk/adaptive.py`): `phase_multiplier` modulates risk sizing by rotation phase (BUY via `PHASE_MULT`; SELL only when `shortable=True` via `SHORT_PHASE_MULT` — spot sells are exits and stay neutral). Combined with track-record multiplier and clamped to [0.5, 1.2]. Phase data is also persisted per signal (`macro_phase`, `btc_dominance`, `btc_dom_change_24h`, `fear_greed` in the feature vector and `market_memory` features) so learning distinguishes altseason from risk-off setups. `scan_analysis.py` applies a phase confidence bonus (±5–15) plus a −5 penalty on altcoin BUYs when BTC dominance ≥ 60.
- Active crypto universe: BTC, ETH, SOL, BNB, XRP, ADA, AVAX, LINK, DOGE (all mapped in `SYMBOL_TO_BINANCE` and `instrument_profile`; `FUT_SYMBOLS` covers funding/basis for BTC/ETH/SOL/BNB/XRP). New crypto assets need entries in the seed assets list AND `CRYPTO_BASES` (`routers/onchain.py`) to get news/onchain context.
- Deriv MT5 execution instance: `tools/mt5-bridge/compose.exec.yaml` + `start-exec.sh` — a SECOND bridge (project `trading-mt5-exec`, own `desktop-exec` Wine volume) targeting Deriv-Demo. Bridge API binds `172.17.0.1:5555` (docker0 only), VNC on `127.0.0.1:26901` for manual Deriv login; credentials belong in the ignored `tools/mt5-bridge/.env.exec.local`. `MT5_READ_ONLY=0` is set there and ONLY there — the sandbox compose remains read-only. Synthetic symbols map to Deriv names in `mt5.connector.ts mapSymbol` (`V75`→`Volatility 75 Index`, `BOOM1000`→`Boom 1000 Index`…). Deriv `stops_level` is large (V75 ≈ $107.7 min stop distance) — sizing rejects undersized stops, never relax it.
